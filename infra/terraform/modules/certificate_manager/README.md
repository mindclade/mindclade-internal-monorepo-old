# Certificate Manager module

Creates regional Google-managed certificates for a regional GKE Gateway, regional
`PER_PROJECT_RECORD` DNS authorizations in the Gateway's project, and only the generated
authorization CNAMEs in existing public Cloud DNS zones.

The general DNS module continues to forbid public CNAME records. This module is the narrow
exception because it receives no arbitrary public record input: names, types, and data come
directly from Certificate Manager. It creates no project, managed zone, Gateway, Kubernetes
Secret, ACME account, or certificate map.

Certificates and authorizations are protected by provider and Terraform deletion guards. A
replacement therefore requires an explicit migration rather than turning a SAN edit into an
unreviewed certificate outage. The caller must enable Certificate Manager in `project_id`,
enable Cloud DNS in `dns_project_id`, and grant the applying identity only the required rights
in both projects.

Every certificate uses exact SANs. Wildcards are rejected so CAA can forbid wildcard issuance
and a new hostname requires an explicit reviewed contract change. Use the `certificate_names`
output as the stable cross-repository value in a regional Gateway's
`networking.gke.io/cert-manager-certs` TLS option.

## Inputs

| Name | Description | Type | Default | Required |
