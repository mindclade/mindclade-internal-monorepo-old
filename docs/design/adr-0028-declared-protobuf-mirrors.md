# ADR-0028: Declared protobuf mirrors bound to the compiled descriptor

- **Status:** Accepted
- **Date:** 2026-08-23
- **Scope:** Every hand-written language type that mirrors a `protocols/proto`
  declaration, and the Go relationship to the generated protobuf bindings

## Context

ADR-0014 makes Protobuf canonical for internal RPC, durable event envelopes,
runtime tickets and snapshots, and worker protocols, and assigns generation to
Bazel: "Go and Python are Bazel action outputs; Rust is generated by the
Bazel-owned Cargo build script. TypeScript is the one checked-in language
projection." It also states that "a concept exposed in several protocols has one
authoritative definition or an explicit mapping with compatibility tests."

That sentence governs protocol-to-protocol mapping. It says nothing about
protocol-to-*language-type* mirroring, and that is where the repository actually
lives.

### Go does not consume the bindings, by construction

Every promoted proto package has a `go_proto_library` — the ten targets are
listed in the `deps` of `//protocols/consumers/_bazel:generated_go_test`
(`protocols/consumers/_bazel/BUILD.bazel`). Exactly two Go files in the tree
import them, and both are tests in the same underscore-prefixed Bazel package:
`protocols/consumers/_bazel/generated_go_test.go`, which asserts only that the
ten packages link and register descriptors, and
`protocols/consumers/_bazel/faults_conformance_test.go`, added to bind one
package to the descriptor. No production Go file imports a generated binding.

That is not an oversight. `go_proto_library` synthesizes
`go.mindclade.dev/protocols/gen/go/...` as a Bazel action output. There is no
`protocols/gen` directory in the source tree, nothing under it is checked in,
and the root `go.mod` module resolves nothing at that path, so a production
import in `control/` or `services/` would break `go build ./...` even where no
layer rule objects. The `_bazel` package name is the mechanism that makes the
two test files legal at all: the Go module loader skips underscore-prefixed
directories, so only Bazel compiles them.

A second, independent constraint applies to the one package that most wants the
types. `libs/go/LAYERS.md` places `faults` in Layer 0 and says those packages
"use only the Go standard library"; the generated bindings pull in
`google.golang.org/protobuf`.

So Go hand-mirrors the wire contract by construction. So does Rust, in two
different ways: `libs/rust/worker_protocol` is a hand-written projection with no
protobuf dependency at all (`tests/integration/cross_language/test_worker_protocol.py`
states this in its module docstring), and `protocols/rust/src/runtime/v1.rs` is
a checked-in prost module that `protocols/rust/build.rs` deliberately points the
generator at through 22 `extern_path` entries rather than generating.

### Three defects trace to the same missing relationship

- **PR #99.** `protocols/proto/mindclade/common/v1/errors.proto` declared 10
  error codes while Go declared 17 and Rust 16, with `canceled`/`cancelled` and
  `not_implemented`/`unimplemented` splits. Rust's `FromStr` hard-errored on
  unknown codes, so a Go-emitted fault failed to parse at the boundary in
  `services/runtime_gateway/src/grpc.rs`. The history is recorded in the module
  docstring of `tests/integration/cross_language/test_error_codes.py`.
- **PR #109.** Rust's `WorkloadKind` (`libs/rust/worker_protocol/src/workload.rs`)
  spelled variants where the proto, Go, Python, and TypeScript spelled them
  differently. It had zero callers, so nothing could fail — the divergence was
  invisible rather than harmless.
- **PR #126's survey.** Mirror pairs that agree today are enforced by nothing,
  and several disagree. Two are verifiable in the tree as written:
  `ERROR_CODE_CANCELED` (`common/v1/errors.proto:35`) and
  `TRAINING_RUN_STATE_CANCELED` (`training/v1/progress.proto:31`) use one
  spelling while `WORKER_STATE_CANCELLED` (`runtime/v1/worker_status.proto:24`)
  and `RUN_STATE_CANCELLED` (`orchestration/v1/run.proto:34`) use the other; and
  `ArtifactLocation` is declared twice under one simple name, as
  `mindclade.common.v1.ArtifactLocation` with `generation` at tag 4
  (`common/v1/artifact_ref.proto:19`) and as `mindclade.artifact.v1.ArtifactLocation`
  with `object_path` at tag 4 and `generation` at tag 5
  (`artifact/v1/artifact.proto:18`). Every field involved is `string`, so a
  mirror wired to the wrong one shifts values with no parse error anywhere.

The common factor is not that the mirrors are hand-written. It is that nothing
records *that they are mirrors*. A relationship no file declares is a
relationship no gate can check, and the existing cross-language checks show the
cost: `tests/integration/cross_language/test_error_codes.py` and
`test_worker_protocol.py` compare source text with regular expressions, which
cannot see a divergence that only exists after compilation and which goes stale
the moment one of the files is formatted differently.

### The one gate that already exists

`tools/codegen/verify_generated.py` (PR #112) closed one trap in this area
already. `.gitattributes:73-76` marks `protocols/**/*.pb.go`,
`protocols/**/*_pb2.py`, `protocols/**/*_pb2.pyi`, and
`protocols/**/*_connect.go` `linguist-generated=true` — rules with no tree
behind them. `check_absent_artifacts` walks each `ABSENT` pattern in
`GENERATED_RULES` and fails if any matching file is committed, and
`check_generated_declarations` fails in both directions if `.gitattributes` and
`GENERATED_RULES` disagree. So the "first `.pb.go` arrives pre-collapsed and
verified by nothing" trap is closed today, and it is closed by a registry that
enumerates its own coverage. That is the pattern this decision generalizes.

## Decision

**1. Generated Go bindings stay Bazel action outputs. `.pb.go` is never
committed.** This reaffirms ADR-0014 and the `ABSENT` disposition already
recorded for `protocols/**/*.pb.go` in `GENERATED_RULES`.

**2. Hand-mirroring a protobuf declaration into a language type is permitted and
expected, but it is a declared relationship, not an incidental one.** Every
mirror is registered in a machine-readable registry under `protocols/mappings/`,
alongside the existing `openapi_proto.yaml`, `event_proto.yaml`, and
`identifier_kinds.yaml` mappings. Each entry names the fully-qualified proto
declaration, the language, the mirroring file, and the conformance target that
binds them.

Keying on the fully-qualified name is load-bearing, not bookkeeping: it is what
forces a mirror of `ArtifactLocation` to say whether it mirrors
`mindclade.common.v1.ArtifactLocation` or `mindclade.artifact.v1.ArtifactLocation`.

**3. Conformance is descriptor-based, not source-text.** A registered mirror's
conformance target must read the compiled descriptor — not the `.proto` text —
and must include a `proto.Marshal`/`proto.Unmarshal` round trip through real
generated messages, so it fails when the two sides agree on names while a
constructor rewrites a value on the way in.
`protocols/consumers/_bazel/faults_conformance_test.go` is the reference shape
for Go, and it is release-blocking: `protocols/consumers/BUILD.bazel` puts it in
the `generated_go_test` suite that `ci/release/targets.yaml` qualifies against.
Python mirrors bind through `py_proto_library` the same way, in
`//protocols/consumers:generated_python_test`; that suite is not yet a
qualification target in `ci/release/targets.yaml`, and making it one is
follow-up work. Rust mirrors bind against the prost types
`protocols/rust/build.rs` generates.

**4. The registry is closed in both directions, and the proto side is the
fail-closed enumeration.** This is the clause that prevents a *new* mirrored
type from shipping without conformance coverage, and it works by enumerating the
authority rather than the mirrors:

- **Proto side.** Every message and enum under `protocols/proto/**` must carry a
  disposition in the registry: `mirrored`, which must name at least one mirror
  and its conformance target, or `unmirrored`, which asserts that no language
  hand-writes it. A declaration with no disposition is an error. The enumeration
  is available: `protocols/compatibility/descriptor_contract.py` already walks
  every message and enum in the descriptor set, and
  `protocols/compatibility/protobuf-v1-descriptor.json` is the frozen surface it
  compares against.
- **Mirror side.** A registered mirror whose file does not exist, whose
  conformance target does not exist, or whose target is not reachable from the
  release-blocking suite for its language is an error. A conformance test the
  release gate does not run is a test that stops mattering the first time it is
  inconvenient.
- **Undeclared-mirror detection.** A Go or Rust type whose name equals the
  simple name of a proto message or enum, in a file the registry does not list,
  is an error. All three defects presented exactly this way — `ErrorCode`,
  `WorkloadKind`, `ArtifactLocation` — because a mirror is normally written by
  copying the name. This heuristic will produce false positives; the escape is
  to record the type in the registry as `not_a_mirror` with a reason, which is a
  reviewed statement rather than a silent exemption. It is deliberately not a
  proof: a mirror that renames every type evades it, and only review catches
  that.

**5. `unmirrored` and `not_a_mirror` are claims, not derivations.** They are
worth recording because they are falsifiable in review and because their absence
is what made the defect class invisible. They are not evidence that no mirror
exists.

## Rejected alternatives

### Check in generated `.pb.go` and adopt the bindings directly

This is the option that looks like it removes the problem, and it does not.

- It reaches at most one of the four languages. Rust hand-mirrors in
  `libs/rust/faults`, `libs/rust/worker_protocol`, and
  `protocols/rust/src/runtime/v1.rs`; PR #109's `WorkloadKind` divergence and
  the Rust half of PR #99 sit entirely outside anything a committed Go tree
  would fix.
- It does not reach the package that produced the live failure.
  `libs/go/LAYERS.md` restricts Layer 0 to the standard library, so
  `libs/go/faults` cannot import `google.golang.org/protobuf` and remain Layer 0.
  Adopting the bindings there requires amending ADR-0009 first.
- It reverses a merged fail-closed gate.
  `tools/codegen/verify_generated.py::check_absent_artifacts` fails on any
  committed `protocols/**/*.pb.go`, and `check_generated_declarations` fails if
  the `GENERATED_RULES` disposition and `.gitattributes` stop agreeing. Adopting
  this option means deliberately changing both, plus adding the byte-comparison
  regeneration path that `REGENERATED` artifacts get, for a tree far larger than
  `sdk/typescript/src/generated`.
- Honestly stated in its favor: it *would* have prevented the Go half of PR #99,
  because Go could not have declared 17 codes against a generated enum of 10.
  That is a real benefit, and it is smaller than the cost above. It is also
  obtainable more cheaply — the conformance binding in
  `faults_conformance_test.go` fails on the same divergence.

TypeScript remains the one checked-in projection because it is an independently
published SDK input, per ADR-0014, and it is byte-compared by the `REGENERATED`
disposition on `sdk/typescript/src/generated/**`. Nothing here changes that.

### Accept hand-mirroring and require conformance, without a registry

This is what PR #126 did for `libs/go/faults`, and the test it produced is the
right shape — it is cited above as the reference. What it does not do is make
itself required of the next mirror. Today nothing in the repository lists which
Go or Rust types mirror a proto declaration, so "every mirror needs a
conformance test" is a rule no gate can evaluate: a checker cannot fail a mirror
it cannot enumerate. Requiring the practice without the inventory is how the
repository got the mirror pairs it has, held together by nothing. The registry is the
difference between a convention and a gate.

### Enumerate the mirrors instead of the proto declarations

A registry keyed only on mirror files would be simpler and would fail open in
exactly the way that matters: a new mirror nobody adds to it is invisible, which
is the present state with extra steps. The proto side is enumerable from the
descriptor, finite, and already parsed by CI, so it is the side that can be made
closed.

## Consequences

- A new proto message or enum cannot merge without someone stating whether a
  language hand-writes it. That is a small, recurring cost on protocol changes,
  paid by the author who knows the answer.
- A new mirror cannot merge without a descriptor-bound conformance target in the
  release-blocking suite for its language.
- Reviewing a mirror stops depending on reading two files side by side. That
  practice is what `faults_conformance_test.go` documents as having failed.
- The registry will start with an inventory that is partly `unmirrored` claims
  nobody has audited. Those are honest placeholders, not evidence.

### Follow-up work this decision requires (none of it lands with this ADR)

1. Add the registry file under `protocols/mappings/`. The natural slot is
   adjacent to `error_codes.yaml`, which is presently an empty scaffold whose
   only content is the comment "Scaffold configuration; promotion requires
   schema validation" and which nothing in the repository reads.
2. Add its JSON Schema, following `protocols/mappings/admission.schema.json`.
3. Add the checker implementing clause 4, wired into the `CHECKS` list of
   `tools/analysis/run_architecture_checks.py` so it runs in `--static-only`.
4. Seed the registry from `protocols/compatibility/protobuf-v1-descriptor.json`
   and record a disposition for every declaration.
5. Register the two mirrors that already have descriptor-bound coverage
   (`libs/go/faults`) or need it (`control/runtime_authority`,
   `libs/rust/worker_protocol`, `libs/rust/faults`), and give the ones without
   coverage a conformance target.
6. Add the `architecture/enforced_decisions.toml` entry once the checker exists.
   It cannot be added now: `tools/analysis/check_enforced_decisions.py` fails if
   a decision's `checker` path does not resolve.
7. Reconcile the `canceled`/`cancelled` spelling split across
   `common/v1/errors.proto`, `training/v1/progress.proto`,
   `runtime/v1/worker_status.proto`, and `orchestration/v1/run.proto`, and
   decide whether the two `ArtifactLocation` messages stay distinct. Both are
   protocol changes governed by `protocols/compatibility/breaking-policy.yaml`,
   not documentation changes.

## Enforcement

Enforced today, by files that exist:

- `tools/codegen/verify_generated.py::check_absent_artifacts` fails on any
  committed `protocols/**/*.pb.go`, `*_pb2.py`, `*_pb2.pyi`, or `*_connect.go`.
- `tools/codegen/verify_generated.py::check_generated_declarations` fails in
  both directions if `.gitattributes` and `GENERATED_RULES` disagree about what
  is generated.
- `protocols/consumers/_bazel/faults_conformance_test.go` binds one mirror,
  `libs/go/faults`, to the compiled `mindclade.common.v1` descriptor with a
  round trip, and `protocols/consumers/BUILD.bazel` makes it release-blocking.
- `tests/integration/cross_language/test_error_codes.py` and
  `test_worker_protocol.py` compare the fault taxonomy and the runtime worker
  protocol across languages. They are source-text scanners by their own
  admission and are a floor, not the mechanism this ADR relies on.

Not enforced yet — clauses 2, 3, and 4 are aspiration until the follow-up items
above land. This ADR is the decision that they must; it is not a claim that they
have. Until then, exactly one mirror in the repository has descriptor-bound
coverage.

## Supersession

A later ADR must explicitly supersede this decision. In particular, committing
generated `.pb.go` requires superseding both this decision and the relevant
clause of ADR-0014, and amending `GENERATED_RULES`; it is not reachable by
changing a gate.
