# Runbook: artifact corruption

## Trigger

A digest mismatch, manifest verification failure, invalid range, decryption
failure, or inconsistent artifact generation is reported by the artifact proxy,
node agent, checkpoint transfer, ingestion worker, or model worker.

## Immediate actions

1. Stop promotion and new consumption of the affected manifest or bundle.
2. Mark the artifact digest and all dependent manifests quarantined in the Go
   registry/control plane.
3. Preserve the failing bytes, manifest, object generation, request ID, tenant,
   producer version, and verification diagnostics; do not overwrite them.
4. Invalidate disposable caches by digest. Do not mutate the canonical object.
5. If model weights, checkpoints, or release evidence are involved, revoke the
   corresponding route/release authority and drain new work.

## Diagnosis

- Verify the manifest signature and schema version.
- Re-read the canonical object directly from durable storage with range reads
  disabled and compare SHA-256.
- Compare object generation/ETag with the committed manifest.
- Inspect producer logs for partial upload, retry, multipart, encryption, or
  atomic-commit failures.
- Determine whether corruption is in durable storage, a local cache, transfer,
  decompression, parser output, or manifest metadata.
- Trace lineage to all downstream datasets, checkpoints, model bundles, and
  evaluations.

## Recovery

- Local-cache corruption: delete the cache entry and refill from verified
  durable bytes.
- Transfer corruption: retry through the qualified Rust transfer path and
  verify before publish.
- Canonical object corruption: restore from an independently verified replica
  or regenerate from immutable inputs under a new digest.
- Manifest defect: issue a new manifest/version; never alter a signed committed
  manifest in place.

## Exit criteria

The root cause is identified, all dependent artifacts are enumerated, affected
routes/releases remain blocked or are safely replaced, regenerated bytes pass
verification, and a regression test/fault-injection case covers the failure.
